Loop 8e14f260 · 28ad29a

An honest clock, and a gate

One clamp was doing two jobs. Every frame was capped at maxDeltaSeconds before anything consumed it — correct for physics, where a 300 ms hitch must never become one 300 ms collision step, and wrong for a score attack, where a game that is visibly running for 300 ms has to cost the player 300 ms. Under a stuttering frame rate the run clock quietly ran slow, and the par timer that decides the speed bonus ran slow with it.

resolveFrameTiming() now splits one browser frame into two numbers, and the phase machine hands each to the systems that should see it: the controller, camera and courier take the capped step; the run timer and the job's elapsed time take the raw one. Paused — a hidden tab — returns zero for both.

Frame arrives 300 ms
Physics step 50 ms
Run clock 300 ms

A 300 ms hitch: collision advances by the cap, the score attack pays full price. Three tests hold this — the split, the paused case, and NaN/negative deltas.

The second commit put a gate under all of it: GitHub Actions running lint, test, typecheck and build on Node 22, plus typed ESLint, so that the checks this log keeps quoting run on every push rather than whenever someone remembers.

Loop 9e87bacf

Knowing where you are

The old HUD pinned a flat arrow to the edge of the frame and pointed it at the objective, on the argument that a map this small does not need a minimap. Playing it says otherwise: an edge arrow tells you a bearing at the exact moment you need a route, and in an alley maze those are different questions.

So navigation moved into the world and onto a map. The minimap is a 192 px canvas that draws the collision world directly — walls dark, props mid-grey, steps skipped — and rotates under a fixed player chevron, so what the courier faces is always up. The objective rides the rim when it is off the map, and sodium means pick up, cobalt means deliver, matching the arrow and the HUD plate. An N marker orbits the edge as the world turns beneath you.

The arrow floats over the courier and points in a straight world-space line at the objective. It deliberately does not bend around corners: the map's three shortcuts are the player's advantage to learn, and an arrow that routes for you hands that away.

Open defect, found by looking at the frames above The arrow is too big and too close. Measured on the spawn frame, it fills 33,472 px — 3.6% of a 1280×720 frame, in a 320×247 px block whose top edge is clipped by the top of the screen. It reads as a HUD element pasted over the street rather than an object in it. The fix is small — less scale, more height, and a distance-aware taper — but it is not made yet, and it is the first thing a player will notice.
Loop 108bb5217

Weight, contact, and things that hold themselves up

Five separate things that all failed the same test — look at it for ten seconds and something is wrong that a screenshot review had waved through.

The jump was a symmetrical parabola, which felt mushy and gave the button no press-versus-hold distinction. Gravity now takes a multiplier by phase: 0.82× while rising with the button held, 1.75× if it is released early, 1.22× falling. A held jump clears a metre; a tap is cut short. It is still a traversal hop, not a platformer jump.

The courier's shoes were 17 cm under the pavement. The torso sat at 0.92 m above the capsule root when the model's soles needed 1.09 m, so every stride sank into the ground. One constant, TORSO_REST_Y, now owns the rest pose, the stride bob and the airborne pose.

Nothing was ever carried. The pickup vanished at the marker and reappeared as a number in the HUD. There is now a real taped parcel between the tucked forearms, with the arm pose forced to react inside the same 12 Hz animation cell as the pickup event, so it does not lag a frame behind the toast.

The menu orbit flew through buildings. The cinematic camera ignored the collision world entirely. The follow camera's obstruction probe was factored out as resolveObstructedCameraPosition() and the menu camera now clamps to the first wall between it and its focus, with clearance for the near plane.

The fire escapes hung in mid-air and climbed past the roof. The courtyard's signature silhouette had no visible support and a third ladder that ended in empty sky above the top landing. Each platform gained two wall plates and diagonal brackets, and ladders are now built only where another landing exists to reach.

Caught by the tests these changes shipped with Five assertions, one per defect: soles at the actor root, parcel visible on the carry frame and gone on delivery, held-versus-tapped jump apex, a cinematic camera clamped in front of a blocking box, and no ladder geometry above the top landing.

Where it stands

Verified in this run, still unproven, and deliberately not started.

Verified

  • 60/60 unit and integration tests pass
  • Strict typecheck, ESLint at --max-warnings 0, and production build all clean
  • 569 kB bundle, 151 kB gzipped, one chunk
  • Zero page errors and zero uncaught exceptions across the run
  • Scene objects and listeners flat across a full job cycle
  • Pickup → carry → delivery → payout → streak, with the parcel in hand for the middle of it
  • All three routes still arrive; 41.7% overall saving

Open

  • The arrow is oversized and clips the top of the frame — 3.6% of a 720p screen
  • The courtyard breezeway saves only 8.8%; the other two shortcuts carry the route-mastery requirement
  • No favicon, so every load spends a 404 on /favicon.ico
  • Gamepad shares one input abstraction with the keyboard but no physical pad has been attached
  • Frame rate is unmeasured on real hardware — the harness renders through software GL, so draw calls and triangles are the honest evidence

Not started

  • Audio of any kind, including audio zones
  • Hazards and light NPC traffic
  • Awnings on the rowhouse runs
  • Brick still tiles visibly at distance
